Title: Team runbook: CreateContainerConfigError because a ConfigMap, Secret or environment variable is missing
Category: Kubernetes / Configuration

Symptoms: the pod stays in the Waiting state with reason CreateContainerConfigError, or the container starts and crashes immediately because a required environment variable is empty. Pod events show configmap not found, secret not found, or could not find key in ConfigMap. There are no application logs when the container was never created.

Diagnosis: read the pod events for the name of the missing object or key. Confirm the object exists in the same namespace as the pod, because ConfigMaps and Secrets are namespaced. Check for a typo in the reference, a deployment applied before its ConfigMap, or an object deleted by a cleanup job.

Remediation: create the missing ConfigMap or Secret, or fix the reference in the deployment. Restarting the deployment after the object exists makes the pod pick it up, and the kubelet usually retries on its own within a minute. Before the object exists, restarting does not help and scaling does not help. A human should supply secret values; the agent must never invent them.

Verification: the pod leaves the Waiting state, reaches Running and Ready, and the application logs show a clean startup.
